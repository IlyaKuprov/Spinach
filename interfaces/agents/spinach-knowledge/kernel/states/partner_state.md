# kernel/states/partner_state.m

- Signature: `[A,descr]=partner_state(spin_system,set_spin,partners)`

## Purpose

Expands fixed states on selected spins across every combination of partner-spin states. The descriptors record the product-state specification for each returned element.

## Inputs

- `set_spin` is a cell array of pairs `{state_label,spin_index}`; for example, `{{'L+',2}}` places `L+` on spin 2.
- `partners` is a cell array of pairs `{state_labels,spin_indices}`. Each `state_labels` entry is a cell array of labels, and each `spin_indices` entry is a vector of spin indices. For example, `{{{'E','Lz'},[1 3]}}` allows spins 1 and 3 to take either listed state.
- Spin indices refer to positions in the spin system, not isotope-list entries. Unspecified spins in the hosting substance retain the `E` state; descriptor padding outside that substance does not populate another block.

## Outputs

- `A` is a cell array of states generated by `state`: density matrices in Hilbert-space formalism or state vectors in Liouville-space formalism.
- `descr` is a cell array of matching product descriptors. Each descriptor has one entry for every spin, in spin-system index order; the specified and partner states occupy their indexed positions.

## Ordering and normalisation

Partner choices are expanded as a Cartesian product, following the partner groups, spin-index lists, and state-label order supplied by the caller. The function does not apply a separate normalisation step: each result is the `state` construction for its descriptor in the configured formalism and basis. The full descriptor spans spin indices `1:spin_system.comp.nspins`; unmentioned positions are `E`.

For example, with five spins, `partner_state(spin_system,{{'L+',2}},{{{'E','Lz'},[1 3]}})` produces four descriptors, in this order:

1. `{'E','L+','E','E','E'}`
2. `{'Lz','L+','E','E','E'}`
3. `{'E','L+','Lz','E','E'}`
4. `{'Lz','L+','Lz','E','E'}`

Each corresponding element of `A` is constructed from that descriptor over spin indices `1:5`.

In segmented systems, all explicitly fixed and partner spins must belong to one substance; genuine cross-substance requests raise `Spinach:which_subst:crossSubstance`. State construction passes only that substance’s descriptor entries and their global spin indices to `state`. Returned `descr` entries still span every global spin and retain `E` elsewhere; those padding identities do not populate unrelated substance blocks.
